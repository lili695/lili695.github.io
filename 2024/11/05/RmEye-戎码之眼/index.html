RmEye-戎码之眼

发表于2024-11-05|更新于2024-11-05
|阅读量:

# RmEye

RmEye 是一个 window 上的基于 att&ck 现代 EDR 设计思想的威胁响应工具。不同于 EDR, 它轻量、高效。自身定位是轻量级威胁检出工具。而不是繁重的、需要付费的、效果不明的所谓的 EDR

# 功能特点

  • 基于 att&ck 设计。所有设计只是为了符合 att&ck 的攻击路径、攻击链 (虽然规则里面没有标注 T 因为懒惰)
  • 轻量、高效。为了不适用繁重超占内存的 ELK 设计思路，而且要保证检出的同时保证不会太重，agent 端使用了大量规则过滤，这样才使得后端使用 sqlite 作为数据库成为可能。单机日志平均一天 4M. 此外轻量级别的客户端一天只占 40-400KB 的内存.
  • 行为检出，让免杀成为过去式。基于 att&ck 设计，只看行为不看文件。文件类免杀已经成为过去式.
  • 高扩展性。可随需求定制功能

# RmEye 之所以不是 Edr/Xdr/Mdr/Ndr/XXXXXdr

  • RmEye 没有流量监控
  • RmEye 仅覆盖 20% 左右的 datasource
  • RmEye 没有联动 WAF、IPS/IDS
  • RmEye 没有实时拦截功能
  • 对 RPC、COM、ALPC 基本无能为力
  • 不支持更高级的扩展检测，如检测脚本、下发规则，主机链
  • 受限于 Sysmon, 很多 att&ck 的 T 没有覆盖，也无法覆盖.
  • 没有响应能力，只能被动记录。请牢记，RmEye 自身定位是轻量级威胁检出工具
  • github 链接：https://github.com/RoomaSec/RmEye

# 安装

  • 运行客户端

    下载 release ( https://github.com/RoomaSec/RmEye/releases ), 里面有客户端，服务端自行 clone 本项目
    服务端是 python3 编写，安装完依赖库后输入

即可部署

服务端部署后，修改 config.py 里面的

MAX_THREAT_SCORE 代表报警分数，意思为进程链总分超过此分数则报警，越高越准但是也会漏报 ALLOW_ACCESS_IP 代表允许的 IP, 只有在此名单里面的 IP 才能访问后台。请增加自己的 IP 地址
客户端则编辑 config.ini

其中 server 改成你的服务端的地址
然后分发三个文件给客户端并且放在同一目录:
config.ini、install.cmd、RmEye.exe、sysmon.xml、Sysmon64.exe
之后管理员身份运行 install.cmd 安装 sysmon 与 RmEye
访问 http:// 服务器 ip:5000 (flask 默认端口) 查看后台
当然一开始啥数据也没有，为了确认是否安装成功可以将 webserver.py 中的

# IOC

目前 RmEye 使用的是 https://metadefender.opswat.com/ 的免费 IOC, 目前的 apikey 仅用于测试，自己部署的时候请务必打开 plugins/ioc_opswat/opswat.py 把 "apikey": "010d4868aef799750e2828fdf17a4d98" 换成你自己的，否做会不安全 (比如其他人能查得到你的请求记录)/ 有使用量限制 (100 次一天). 所以务必换成你自己注册的账号。这个 IOC 源是免费的而且好用的，比 OTX 好用
