# 1、缘起

刚开始研究⼤模型安全的时候就看到 huggingface/transformers 有这个 load_repo_checkpoint 的漏洞，不过 当时看到说是利⽤起来⽐较困难就没有再深⼊研究（世上⽆难事，只要肯放弃），直到周五（2024-10-18）的时 候，看到各个技术群⾥都在转发字节跳动实习⽣对⼤模型投毒的聊天记录，故事情节相当精彩刺激，后来在知乎热 榜上也看到出现⾮常多的讨论，有兴趣的读者可⾃⾏吃⽠： 字节跳动大模型训练被实习生恶意注入破坏代码，涉事者已被辞退，攻击带来的影响有多大？暴露出哪些问题？ - 知乎 (zhihu.com) 既然这个漏洞都已经能够在实际环境中产⽣危害了，感觉是有必要深⼊了解分析⼀下了

# 漏洞原理分析

从⼤的流程上来说，就是 transformers 允许从检查点恢复预训练的⼀些进度，⽽所谓的 checkpoint 检查点其实 就是⼀个⽂件夹，结构⼤概是这样⼦的：

⽂件夹名称 checkpoint 是约定的固定的名称，下⾯的两个⽂件：

  • weights.h5 ：模型的权重⽂件，必须要是跟正在使⽤的模型架构对应的的权重，否则的话加载权重这⼀步就 会抛异常，⾛不到执⾏命令那⼀步，所以利⽤时要知道使⽤的是哪个模型架构，因为不同的架构可能有不同的 神经⽹络层数之类的
  • extra_data.pickle ：这个⽂件的初衷是存放⼀些元数据信息，只是保存⽅式选择的⽅式选择得不太合适， 为了⽅便直接⽤ pickle.dump 来保存，输出的是⼀个序列化的⽂件，⽽模型加载的时候要读取对应的元数据 信息，就会使⽤ pickle.load (f) 来加载这个⽂件，从⽽利⽤反序列化漏洞进⾏ RCE。
